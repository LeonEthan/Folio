# Design authoring intake

`@folio/design-authoring` migrates the PPTD **intake** subset of the upstream
authoring pipeline into Folio: fail-closed PPTD snapshot validation, PPTD →
BentoDoc v4 import, BentoDoc schema-version migration, and secure authoring
snapshot collection. It also carries the bundled Agent skills
(`skills/graphic-design`, `skills/imagegen`) that the CLI materializes into
design-session workdirs.

Sources: repository https://github.com/LeonEthan/agentic-listing-design pinned at
`7fd3c0691876ec7428fe3f3ef1ef6c4c46cdef12` (Bento submodule
`813c71fff72491e6898f5e55a20da44a562be586`, MIT). The original repository has no
root license file. `source-manifest.json` records every migrated file with its
upstream path, derivation (`verbatim` / `adapted` / `ported` / `rewritten`), and
hashes; `scripts/build.mjs` re-verifies verbatim files on every build. The imagegen
skill ships the upstream MIT `LICENSE.txt`.

## Scope

Migrated (`src/`):

- `validate.ts` — fail-closed PPTD validator (filesystem `validate()` and
  immutable-bytes `validateSnapshot()` variants) driven by the frozen capability
  matrix.
- `intake.ts` — `intakeAuthoring(entryRel, snapshot)`: validate → bind semantic
  assets by exact bytes → import; tri-state result (`ok` / `invalid` /
  `unsupported`).
- `import.ts` — deterministic PPTD → BentoDoc v4 import (only accepts
  validator-branded documents).
- `migrate.ts` — `loadBentoDocV4` pinned v1/v2/v3 → v4 migration chain.
- `richtext.ts`, `semantic-assets.ts`, `product-boundary.ts`, `latex.ts` —
  single-point syntax/enumeration/boundary modules the above depend on.
- `collect-authoring.ts` — secure snapshot collection (allowlist relpaths,
  symlink/hardlink/escape rejection); Folio admits exactly one entry,
  `design.pptd`.

Contracts types and the frozen capability matrix come from
`packages/design-bento/vendor` (the pinned vendored snapshot), reached through the
single `src/contracts.ts` seam. The matrix JSON is embedded at build time into
`src/generated/capability-matrix-bytes.ts` and re-verified at module load against
`FROZEN_MATRIX_SHA256`, so consumers under bundling (CLI vite SSR, skill esbuild)
see byte-identical validation.

Not migrated (by decision): the immutable revision CAS store (`revisions.ts`,
`workspace.ts`), quality orchestration, PPTD authoring generators beyond intake,
the full upstream PPTD language catalogue (`references/pptd.md`), the imagegen
Python CLI and its deployment-specific references, and `skills/amazon-aplus`.

## Skills

`skills/graphic-design/` is the agent-facing authoring skill: PPTD method
references, a validated minimal example, and three Node scripts that run
self-contained in a materialized session workdir:

- `scripts/finalize.mjs` — thin entry over the bundled shared validator
  (`scripts/lib/folio-pptd.mjs`, esbuild output, regenerated by `pnpm build`);
  validates a `design.pptd[.tmp]` draft and promotes a clean `.tmp`. It is a
  self-check convenience, not a gate: the daemon re-validates at intake.
- `scripts/render-preview.mjs` — runs the same intake (collect + validate +
  import) locally, then reports honestly that visual rendering is provided by the
  `folio_render_preview` MCP tool when connected.
- `scripts/reference-pack.mjs` — dependency-free Node port of the upstream Pillow
  inspection tool (pack: meta/grid/bands/palette; crop). PNG is fully decoded via
  `node:zlib`; JPEG/GIF/BMP/WEBP report dimensions but raster artifacts require
  PNG. Ported because neither Folio nor the migrated intake covers reference-image
  measurement, grid overlay, palette extraction, or raster cropping, and the
  reconstruction workflow needs them.

`skills/imagegen/` keeps the upstream prompting method, rewritten for the
`folio_generate_image` MCP tool (registered only when the user configures and
enables an image connection). Runtime per-file `VENDOR.lock` freezing is replaced
by this package's build-time source manifest.

## Build and test

```sh
corepack pnpm --filter @folio/design-authoring build      # manifest verify + matrix embed + skill bundle
corepack pnpm --filter @folio/design-authoring typecheck  # build first, then tsgo
corepack pnpm --filter @folio/design-authoring test       # build first, then vitest
```

The CLI build (`prepare:design-authoring`) runs the same build before staging
skill directories into the CLI dist; see `apps/cli/scripts/copy-design-skills.js`.
