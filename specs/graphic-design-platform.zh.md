# Folio 平面设计工作台

Status: draft
Translation: pending

## 使用场景

用户发起设计会话，输入需求并添加参考图，使用本机 Agent 生成可编辑的平面设计；随后通过选中元素对话或手工修改，保存、重开并导出图片。用户通过会话历史查找历史产出，不管理独立作品目录。正常创作不要求 Git 仓库、分支、终端命令或代码审查知识。

核心目标是将成熟的 Lody coding-agent 工作台经验与 PPTD + Bento 可编辑设计能力结合，形成 Agent 自主使用的设计环境（agent-naive），复用现有工作范式。

本草案根据已获方向性认可的改造清单制定，具体行为仍待复核。已实现 P0 固定样稿、P1 手工编辑及 P2 Agent 设计闭环；阶段证据见文末，不表示整个产品已获视觉或发布验收。

## 产品范围

- 本地单人桌面工作台；每个作品一个静态画布，项目可组织多个作品。
- 覆盖海报、封面、社交配图、横幅、信息图、长图和通用电商图片；场景知识放在技能和参考材料中。
- 保留 Folio 现有桌面架构、UI 设计语言、Agent 接入及本地会话能力；迁入 Bento 的文档、编辑和渲染能力。
- 整个迁移计划不包含独立素材库、跨作品素材浏览或复用，也不将其顺延至后续迁移阶段。保留当前画布的图片插入、替换、选中图片重新生成及文档所需素材持久化；回合参考图附件是独立需求。
- 首期交付 PNG/JPEG。多画板、演示文稿、视频、模板市场、云协作及其他专业格式不属于本草案。

首页保留原有顶部与对话输入结构，尺寸选择与项目目录处于同一行最右侧，右边缘对齐输入框，不单独堆叠一行，不提供独立的新建设计按钮或名称输入。尺寸默认 Auto，不要求预填宽高；切换自定义后才显示并校验宽高。输入内容并按回车时复用现有 Session 提交及自动命名流程，同时初始化空白单画布作品；Auto 在 P1 使用默认初始画布，后续可在编辑器调整，尚不承诺 Agent 根据内容自动计算尺寸。创建失败保留输入草稿。提交沿用现有 Agent 配置要求，作品打开后的手工编辑不依赖 Agent 执行。

## 职责和持久化

设计产出保存在会话使用的本地 workspace 中，只维护最新状态。会话历史记录交流过程，不提供各回合画稿快照或历史版本打开能力。设计会话记录讨论和执行过程，首期默认一个作品对应一个主会话。会话归档和删除沿用原项目语义，不新增删除普通 workspace 文件的行为；删除会话记录不等于删除本地设计文件。既有 Git worktree 清理规则不因此改变。

现有 CLI 后台继续负责 Agent 生命周期、权限回应、会话与回合。设计服务负责格式转换、结构校验、素材登记、版本校验、候选保留及当前画稿保存；Electron 负责桌面资源、可信编辑器桥接、渲染进程与原生文件交互。设计服务不另建一套 Agent 调度和聊天存储。

BentoDoc 是当前画稿的唯一权威状态（canonical）；PPTD 是 Agent 可读取和修改的文件表示，按需从当前画稿生成，Agent 修改后的 PPTD 经校验再提交为 BentoDoc。画稿投影与 Agent 创作草稿具有不同用途，不构成两个可独立提交的权威当前稿。预览图和导出图是派生产物。现有 Loro/Flock 保存会话及作品关联，本地 workspace 保存当前画稿与素材，不把两者变成可分别修改的重复画稿。

会话及产物身份是关联依据；并发保存的基线标识只用于检测状态变化，不表示保存历史版本。会话元数据的写入或通知失败不得撤销已持久化的作品；重开时能根据已持久化的关联恢复，具体提交与修复机制在技术切片中确定。用户不应因通知迟到而重复生成同一作品。

## 编辑和 Agent 回合

P1 支持宽高各 1–4096 像素的单画布，手工调整画布尺寸时保持元素位置和大小；若调整后有元素超出画布，拒绝该调整并说明阻塞元素，不自动缩放或裁切。

1. 提交设计输入前确认当前编辑已保存，并固定作品、当前稿基线、选区、参考材料与本次设计技能；保存失败时保留用户输入并说明原因。
2. 模型、权限和工具能力由当前 Agent 的真实能力决定；不伪造支持状态，不静默切换 Agent，也不代替用户回答权限请求。
3. Agent 自然完成后收集并校验候选；文件出现不代表完成，Agent 回合成功也不等于有效画稿已经提交。
4. 人工编辑和 Agent 候选通过同一设计服务提交，在提交锁内原子核对基线。基线已变时保留当前稿与候选，交由显式采用或 Agent 重新读取后修改；迁移不包含元素/属性级自动合并，即使双方改的是不同属性也不承诺自动合并。
5. 重新生成或冲突的候选提供当前稿/候选查看、采用和拒绝，不要求完整基线/当前/新稿三方对比。采用时再次核对当前状态，重复请求不能重复应用；拒绝不改变当前画稿。
6. 失败、取消、缺失产物、校验失败及候选待处理分别呈现。重启不自动重新发起模型调用；继续动作沿用现有恢复合同。
7. 元素引用携带作品、当前稿基线及稳定元素 ID；选区失效时明确提示，不猜测另一元素作为目标。

## 当前画稿读取与文件一致性（P3 目标）

以下是待实施的 P3 合同，P2 验收不覆盖反向转换和 hook 接入。

- 画布独立编辑、渲染、保存并提供通用 snapshot/flush；画布编辑事件不触发面向 Agent 的 PPTD 回写，不依赖 Agent 回合状态。
- Agent 读取当前设计时，由读取路径上的 hook 请求设计服务取得包含已完成手工编辑的一致快照，并按需同步为 PPTD 及配套素材。成功读取对应一个明确版本；同步失败或状态不能稳定时明确报错，不能把旧文件声称为最新画稿。读取后的再次编辑由版本检查识别；提交保护也覆盖已完成但尚未落盘的手工编辑，不能在提交重载时抹掉它们。
- BentoDoc → PPTD → BentoDoc 保持支持范围内的可编辑语义、稳定元素 ID、层级、样式和素材引用；不承诺还原原 YAML 的排版、注释或别名。无法表达的内容明确失败，不静默丢弃或栅格化。
- 不以提示词要求调用 `read_design` 作为唯一保护，也不要求新增同名工具。复用各 Agent 的真实工具 hook/extension：受控写入已有设计必须具有成功读取建立的、绑定作品/草稿/版本的基线；缺失或过期则拒绝该写入并返回可处理的原因。写入前临时同步不能使旧参数自动获得新基线。
- 当前稿投影与 Agent 工作草稿分离；同步或再次读取不得覆盖草稿中的修改，也不得静默更新该草稿的提交基线。派发时冻结的回合输入保留原始事实，后续读取基线单独关联对应创作尝试。
- hook 只实施数据和版本前置条件，不规定调研、生成、自检或评审顺序。仅在工具成功返回对应内容后记录读取事实；它证明已提供内容，不证明模型理解内容。运行时错误、未覆盖工具或绕过 hook 时，canonical 提交仍必须执行独立的原子基线检查。
- 应用生成的当前稿投影不作为 Agent 的新产物收集。各 Agent 的具体运行版本、启动方式及 Read/Edit/Write/Shell/MCP 覆盖必须逐一验证；部分接入不支持时展示真实能力，不承诺全局 shell 拦截或完整沙箱。

设计建议和可选辅助工具放在 skill；应用只做结构校验和可观测结果分类，不强制工具调用次数、视觉自检轮数或固定完成流程。工具缺席不推断 Agent 自带能力缺席。正式导出继续采用固定 Bento 渲染路径。

## 创作文件实时预览（P3 目标）

用户可在 Agent 创作或外部编辑器写入当前会话 PPTD 文件期间，查看最新有效的只读预览。实际文件变化触发受限快照采集、结构校验与已有 PPTD → BentoDoc 转换；工具事件只作补充，不为五种 Agent 分别建立预览机制。该链路不参与 Agent 调度或完成判断。

- 仅为实际打开的创作预览建立订阅，同一 workspace/入口的消费者共享监听与转换；最后一个消费者离开或断开后释放。无预览消费者的历史 workspace 不监听、不持续转换；后台回合仍沿用正式产物采集。
- 监听 `design.pptd`、引用页面和必要素材目录；为发现首次创建、rename 替换及缺失依赖，可非递归监听最近合法父目录并过滤。依赖改变时调整目标，不递归监听整个 workspace。建立订阅后核对初始文件，重开、恢复连接、手动刷新及有消费者的回合结束主动核对，补偿遗漏通知。
- 合并连续事件，按依赖集合与文件字节跳过重复转换；设置有限的等待和重采策略，避免持续写入造成无期限等待或忙重试。固定同次观测的文档与素材字节并复核稳定性后转换，不把防抖、逐文件读取或结构有效当成作者已完成多文件事务。有效的中间稿可以预览，不能据此认定产物完成。
- 转换/渲染按项目合并调度，结果绑定源摘要、作品和订阅代次；旧任务不得覆盖较新结果或更新已切换的视图。无效中间状态、暂缺素材和读取不稳定时保留上一份有效预览并标明状态；首次尚无有效结果时显示等待，不能清空可编辑当前稿或把回合判失败。监听失败显示自动更新不可用并支持主动刷新，正式采集不受影响。
- 工作台区分“当前画稿（可编辑）”和“创作预览（只读、未提交）”。切换视图保留当前稿的未保存编辑和撤销状态；读取 hook 始终以当前稿为对象，不因用户正在查看预览而切换输入来源。
- 首期 Agent 运行中不采用预览。回合完成后仍独立采集、校验和提交；已安全提交的结果直接打开，待处理候选沿用显式采用/丢弃。没有运行回合时，当前会话中的外部 PPTD 修改可显式导入为候选并采用；不新增作品目录导入产品。失败/取消不因曾预览成功而自动变为可采用的成功产物。
- 采用绑定用户已看到的文档与素材快照，后续文件变化不能偷换该内容；无法继续采用原快照时重新呈现。采用仍执行当前稿原子版本检查并保护未落盘手工编辑，无读取基线时不伪造基线。只有经正式采用/提交后才进入当前稿编辑和正式导出。
- 预览不推进当前稿版本、不改变 Agent 草稿基线、不触发保存或完成。应用产生的 PPTD 投影、正式存储、预览缓存和导出文件不作为创作入口监听或 Agent 新产物收集，避免同步循环；不使用“忽略下一次事件”推断来源。

## 保存、恢复和导出

- 自动保存、切换作品、关闭标签和退出应用共享保存确认语义。失败必须可见，不能声称已保存；运行时与画稿保存采用各自真实状态。
- 切换作品、关闭标签或退出时保存失败，阻止该动作并保留未保存修改；用户可重试或明确放弃修改，不能静默丢稿。
- P1 并发保存发现基线过期时拒绝写入，保留本编辑器的未保存修改；用户可另存为独立作品，或明确放弃修改并重新加载已保存当前稿。不自动覆盖或合并；Agent 候选按上述显式处理合同实施。
- 冲突另存创建新作品及空白主设计会话，将画稿与必需素材复制到新会话的 workspace，原作品保持不变；不复制交流记录或撤销历史。另存失败时保留未保存修改，并继续阻止切换、关闭或退出，直至保存成功或用户明确放弃。
- 意外崩溃或断电后恢复最后成功保存的画稿及素材；仍处于待保存或保存中状态的修改可能丢失。P1 不承诺崩溃恢复未确认保存的草稿，正常离开动作仍执行保存保护。
- 当前不提供画稿历史版本、版本列表或历史恢复，也不迁入不可变修订库。未来若提供历史还原，再基于 Git 单独设计；编辑器当前运行中的撤销/重做不构成持久化历史承诺。
- 作品标签仍打开时，切换作品或视图保留该编辑器的撤销/重做状态；关闭标签或重启后不保留撤销历史，已保存当前画稿不受影响。
- 正式导出基于已保存的当前画稿，使用固定编辑器渲染路径、字体和素材。导出前处理当前未保存修改，不能悄悄导出旧稿。
- PNG 保留透明度；JPEG 透明区域填白。像素尺寸按画布实际尺寸输出；缩放仅影响界面显示。
- 无效文档、缺失素材、字体或渲染失败须报错，不用占位图或窗口截图冒充成功导出。
- 首期不提供作品目录管理或相邻项目作品目录导入功能；旧程序数据保持原状。

## 工作台与边界

保留侧栏、标签页和对话输入结构；默认对话与较大画布并排，提供专注画布模式。图层和属性按需展开，图片操作随当前画布选区呈现，窄窗口切换视图时保留编辑状态。去掉幻灯片、演示及其他不支持的编辑器入口。

Git/PR/CI 等开发功能退出设计主流程，并停止其不再需要的后台工作。共享基础设施只在确认没有消费者后删除。终端、参考网页浏览、会话分叉按实际消费者逐项决定；通用文件、进程、工具、诊断、权限和恢复能力继续复用。新应用身份与数据目录须与现有 Lody 和相邻程序隔离。

遵循 [平台边界](../packages/platform/AGENTS.md) 和 [共享协议合同](../packages/shared/AGENTS.md)：不引入认证产品云请求或遥测。用户选择的 Agent 及图像服务仍可能访问外部模型，本地优先不等于离线生成；凭据不进入画稿、Role 或日志。没有 Agent 或图像服务时，已有作品仍可编辑、保存和导出。

## 待定项

- 首个真实设计验收使用当前可用接入，不绑定特定 Agent。Pi 与其他 coding agent 一样属于用户侧选择，不是 Folio 的前置依赖；具体能力以各接入的验证结果为准。
- P0 以 macOS 实机开发版及安装包通过为阶段门槛；Windows/Linux 同期执行构建与资源探针。首发操作系统及架构矩阵仍待实机证据确定。
- P3 的画稿投影、Agent 草稿和读取基线沿用现有 workspace；具体文件布局与各接入 hook 配置方式待实现切片确定，不覆盖用户全局配置。
- OSS 桌面把参考图作为回合附件（P2-A3）仍待处理：独立素材库已取消，P3 当前画布图片操作不吸收此项。可选诚实缺席（不提供会失败的纸夹）或独立的本地会话图片存储；未裁定。
- P2.7 #2b 的“未修改旧 PPTD 仍可成为候选”保留原实施决定，结合新输入/草稿边界再裁定，不在本次文档修订中直接改变行为。
- 参考图非 PNG 的能力缺口仍待裁定：评估派发边界使用实际可用的解码能力规范化 PNG，或明确产品限制；不扩写自制编解码器，也不把 CLI 持有图片字节等同于拥有解码器。
