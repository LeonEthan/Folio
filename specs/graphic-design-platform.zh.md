# Folio 平面设计工作台

Status: draft
Translation: pending

## 使用场景

用户创建一个设计项目，输入需求并添加参考图，使用本机 Agent 生成可编辑的平面设计；随后通过选中元素对话或手工修改，保存、重开、恢复历史并导出图片。正常创作不要求 Git 仓库、分支、终端命令或代码审查知识。

本草案根据已获方向性认可的改造清单制定，具体行为仍待复核，尚未实现。它不表示已有运行、视觉或发布验收。

## 产品范围

- 本地单人桌面工作台；每个作品一个静态画布，项目可组织多个作品。
- 覆盖海报、封面、社交配图、横幅、信息图、长图和通用电商图片；场景知识放在技能和参考材料中。
- 保留 Folio 现有桌面架构、UI 设计语言、Agent 接入及本地会话能力；迁入 Bento 的文档、编辑和渲染能力。
- 首期交付 PNG/JPEG。多画板、演示文稿、视频、模板市场、云协作及其他专业格式不属于本草案。

## 职责和持久化

项目组织作品；作品具有稳定身份、当前修订及历史。设计会话记录讨论和执行过程，首期默认一个作品对应一个主会话。归档会话不销毁作品，复制作品不等同于延续原 Agent 会话。

现有 CLI 后台继续负责 Agent 生命周期、权限回应、会话与回合。设计服务负责文档校验、素材登记、候选协调及修订提交；Electron 负责桌面资源、可信编辑器桥接、渲染进程与原生文件交互。设计服务不另建一套 Agent 调度和聊天存储。

BentoDoc 是每个修订唯一可编辑文档；PPTD 是创作输入，预览图和导出图是派生产物。现有 Loro/Flock 保存会话及作品关联，设计修订存储保存画稿和内容寻址素材，不把两者变成可分别修改的重复画稿。

作品及修订身份是关联依据。会话元数据的写入或通知失败不得撤销已持久化的作品；重开时能根据已持久化的关联恢复，具体提交与修复机制在技术切片中确定。用户不应因通知迟到而重复生成同一作品。

## 编辑和 Agent 回合

1. 提交设计输入前确认当前编辑已保存，并固定作品、基线修订、选区、参考材料与本次设计技能；保存失败时保留用户输入并说明原因。
2. 模型、权限和工具能力由当前 Agent 的真实能力决定；不伪造支持状态，不静默切换 Agent，也不代替用户回答权限请求。
3. Agent 自然完成后收集并校验候选；文件出现不代表完成，Agent 回合成功也不等于有效画稿已经提交。
4. 人工编辑和 Agent 候选通过同一设计服务提交。写入检查预期修订；不冲突的修改可协调，无法证明安全的修改保留为独立候选，不能覆盖当前稿。
5. 重新生成的候选提供比较、采用和拒绝。采用时再次核对当前修订，重复请求不能重复应用；拒绝不改变当前画稿。
6. 失败、取消、缺失产物、校验失败及候选待处理分别呈现。重启不自动重新发起模型调用；继续动作沿用现有恢复合同。
7. 元素引用携带作品、修订及稳定元素 ID；选区失效时明确提示，不猜测另一元素作为目标。

## 保存、恢复和导出

- 自动保存、切换作品、关闭标签和退出应用共享保存确认语义。失败必须可见，不能声称已保存；运行时与画稿修订采用各自真实状态。
- 历史恢复保留原有修订，恢复后编辑产生后续修订；撤销/重做与持久化历史恢复是不同操作。
- 正式导出基于明确的已保存修订，使用固定编辑器渲染路径、字体和素材。导出前处理当前未保存修改，不能悄悄导出旧稿。
- PNG 保留透明度；JPEG 透明区域填白。像素尺寸按画布实际尺寸输出；缩放仅影响界面显示。
- 无效文档、缺失素材、字体或渲染失败须报错，不用占位图或窗口截图冒充成功导出。
- 导入隔壁项目作品采用显式复制、格式验证与完成后登记；原目录保持不变。不承诺迁移聊天、旧 provider 句柄或执行检查点。

## 工作台与边界

保留侧栏、标签页和对话输入结构；默认对话与较大画布并排，提供专注画布模式。素材、图层、属性和版本按需展开，窄窗口切换视图时保留编辑状态。去掉幻灯片、演示及其他不支持的编辑器入口。

Git/PR/CI 等开发功能退出设计主流程，并停止其不再需要的后台工作。共享基础设施只在确认没有消费者后删除。新应用身份与数据目录须与现有 Lody 和相邻程序隔离。

遵循 [平台边界](../packages/platform/AGENTS.md) 和 [共享协议合同](../packages/shared/AGENTS.md)：不引入认证产品云请求或遥测。用户选择的 Agent 及图像服务仍可能访问外部模型，本地优先不等于离线生成；凭据不进入画稿、Role 或日志。没有 Agent 或图像服务时，已有作品仍可编辑、保存和导出。

## 待定项
