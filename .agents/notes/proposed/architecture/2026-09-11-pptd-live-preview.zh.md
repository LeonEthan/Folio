# PPTD 文件变化驱动的实时预览

Status: proposed
Translation: pending

## 摘要

现有 PPTD 主要在回合结束采集或 Agent 请求预览时转换，用户难以在创作中看到文件的最新有效结果。本方案为打开的设计预览建立按需文件订阅，复用现有采集、PPTD 导入与 Bento 渲染，更新独立的只读预览。文件变化不代表产物完成，也不提交当前稿；画稿读取 hook 和最终版本检查保持原职责。首期 Agent 运行中不采用预览，完成后沿用正式提交或候选采用，外部编辑文件在没有运行回合时可显式导入；跨文件读取只能验证观测到的稳定状态，不能推断作者已经完成一组编辑。

## 结论与既有方案的关系

方向合理，可纳入 P3；本次只修订设计文档和阶段计划，没有运行时代码实现。它补充[同步与 hook 决策](2026-09-10-design-sync-hooks.zh.md)，不替代读取基线、草稿隔离或 canonical 原子提交。产品合同由 [Spec](../../../../specs/graphic-design-platform.zh.md)表达，工作拆分见[阶段计划](2026-09-09-graphic-design-platform.zh.md)。

| 边界 | 唯一职责 |
| --- | --- |
| 文件订阅与预览转换 | 观察创作 PPTD 及依赖字节，生成只读 Bento 预览 |
| 读取 hook | 从含手工编辑的当前画稿生成 PPTD 投影，记录成功读取基线 |
| 写入 hook | 对受控的已有设计写入核对读取基线 |
| 正式采集/提交服务 | 判断回合产物，结构校验、原子核对当前稿版本并持久化 |
| Bento 画布 | 独立编辑、渲染、通用 snapshot/flush；不管理 Agent 生命周期 |

文件通知覆盖 Write、Edit、patch、Shell、脚本和外部编辑器，无须为五种 Agent 分别实现预览。工具完成只能补充刷新。采用文件驱动的开发工具职责划分，不引入 Vite、HMR 协议或新的 Agent 调度系统。

## 复用依据和实际缺口

- [buildPreviewPayload](../../../../apps/cli/src/design/render-preview.ts)已复用 `collectAuthoring → intakeAuthoring` 构造包含文档与素材的预览载荷，不提交当前稿。[intakeAuthoring](../../../../packages/design-authoring/src/intake.ts)从固定字节校验、绑定素材并调用 [importPptd](../../../../packages/design-authoring/src/import.ts)。新增持续预览复用这条转换链；采集和缓存可在既有设计模块内扩展，不复制 validator/importer。
- [collectAuthoring](../../../../packages/design-authoring/src/collect-authoring.ts)已有路径白名单和链接检查，但当前逐文件读取 `design.pptd`、`pages/`、`media/`，没有跨文件事务或整次采集前后稳定性校验。不能将其现有 Map 返回值或防抖直接称为跨文件原子快照；需补齐受限依赖闭包和读取稳定性机制。
- [WorkspaceWatchCoordinator](../../../../apps/cli/src/lib/code-collab/workspace-watch-coordinator.ts)已有根目录共享订阅、释放、代次和 watcher 错误处理；[watch plan](../../../../apps/cli/src/lib/code-collab/workspace-watch-plan.ts)当前仍递归监听非忽略的顶层目录。先评估为该基础设施增加精确目标订阅/拆出可复用底层；不能直接开启 Code Collab 索引、All Changes 或全 workspace 扫描，也不复制另一套 broker/进程恢复系统。
- [FilePreviewService](../../../../apps/cli/src/lib/file-preview/file-preview-service.ts)明确负责单文件读取，不开启 workspace watcher；保留该边界。设计服务承载 PPTD 项目的订阅与转换，桌面复用 [Bento 宿主](../../../../apps/electron/src/main/services/design-service.ts)的渲染资源和受控桥接，具体只读载荷接入待 P3 验证。不把每次变化都转为一次 `folio_render_preview` MCP 调用或 PNG 文件生成。

## 按消费者建立订阅

1. 打开实时预览时确定作品、canonical workspace 路径、创作入口及来源身份；先建立监听，再读取并核对初始文件，覆盖订阅初始化窗口。打开可编辑当前稿本身不要求监听所有创作文件。
2. 同一 workspace/创作入口的消费者共享 watcher 和转换结果，各自绑定订阅代次。最后一个消费者离开后释放订阅、任务和临时素材；失联窗口也需由既有连接生命周期释放。无消费者的历史 workspace 不监听、不转换。
3. 有效目标限制在 `design.pptd`、被引用页面及必要素材目录。为发现首次创建、原子 rename 替换、删除后重建及尚缺的引用，允许监听这些目标的最近合法父目录，非递归且过滤文件；不因文件暂缺扩大成全 workspace 递归监听。
4. 引用图变化时重建受限目标集合，建立新目标监听后复查再释放旧目标。无效 manifest 期间保留最后已知目标及必要父目录，等待修正；通知不携带可信路径授权，所有读取继续执行既有路径、类型、大小和资源限制。
5. 重开、重新连接和主动刷新时重新核对文件；有消费者的回合结束补一次核对。无消费者的后台回合只走现有正式采集，不启动预览链路。

## 快照、更新顺序与失败

文件事件只是 dirty 信号。合并连续事件，并为当前依赖集合及文件内容建立摘要；只有字节或依赖改变才重新转换。同名素材的字节变化也必须触发更新，不能只比较文件名、大小或修改时间。合并策略包含最大等待上限，避免持续写入一直推迟尝试，但不要求每个写事件都转换。

读取时复用安全采集，在读取前后核对依赖集合与内容，必要时有限重采；将确认的字节 Map 固定后交给同一 intake 和渲染载荷。转换/渲染都使用捕获的素材字节，不重新从正在变化的目录读取素材。连续变更不能阻塞 CLI 会话处理：限制单项目在途转换为一个、待处理仅保留最新请求，并验证执行预算，具体隔离方式优先复用现有资源。

这里的“一致”指同一次已固定、经过依赖与结构校验且在复核中未观察到变化的输入，**不承诺任意外部多文件写入的原子事务**。即使两次采集相同、内容有效，也可能是作者停顿在一个有效中间稿；允许预览它，不能将它认定为完成。若未来要求作者事务一致性，需要生产者发布协议，应另行设计，不由 hook 或强制 finalize 流程代替。

每次输入变化递增请求代次；转换和渲染结果发布前再次核对源摘要、作品和订阅身份，旧结果不能替换更新的请求结果。消费者关闭、切换或连接重建后，旧任务即使完成也不发布。素材缓存按内容与快照身份隔离，避免同路径图片的旧缓存污染新预览。

读取不稳定、文档暂时无效或素材暂缺时保留上一份有效预览，并明确“更新中/等待有效文件”及来源摘要；尚无有效结果时显示等待状态，不能把空白当前稿伪装成实时结果。最后有效预览不是最新文件的成功承诺。持续格式错误、权限拒绝、越界或资源超限提供可见诊断，不持续忙重试，更不绕过校验。

监听失败时显示自动更新不可用及手动刷新入口；恢复连接、重新打开和回合结束通过主动核对补偿遗漏通知。不能承诺 watcher 永不丢事件，也不为补偿而轮询所有 workspace。预览失败只影响该消费者的可见状态，不把 Agent 回合判失败、不自动修复文件、不重试模型，正式采集与提交仍独立执行。

## 已确认的 UI 和采用边界

用户确认首期采用以下边界；具体控件布局仍在 P4 适配现有侧面板。

- 在现有设计侧面板中明确区分“当前画稿（可编辑）”与“创作预览（只读）”。后者标明 PPTD 文件来源及尚未提交；只有可核实来源时才进一步标注 Agent/外部编辑，不根据文件事件猜测写入者。普通预览切换不重建或覆盖当前稿编辑器，保留其未保存修改和撤销状态。无需增加独立预览管理页面。
- Agent 运行中可以查看实时预览、切回当前稿手工编辑；首期不允许将运行中的预览采用为当前稿。这里的运行中指同一创作 workspace 的相关回合；按钮状态与服务端采用校验使用既有执行状态，不能仅靠 UI 禁用防止竞争。画布仍不感知 Agent 生命周期。
- 回合完成后独立执行正式采集。若现有规则已安全提交，直接打开已提交当前稿；若形成待处理候选，通过已有显式采用/丢弃进入编辑，不为已提交结果增加一次重复确认。失败/取消不因曾成功预览而自动生成可采用的成功结果。
- 外部编辑器修改的是当前会话 workspace 的 PPTD 创作文件；没有运行回合时可显式导入为候选并采用，复用结构校验和版本保护。这不是作品目录导入、历史版本库或新建素材库。不存在有效基线时不能推断基线，显式采用要针对用户已看到的当前稿版本。
- 采用针对用户已看到的确切文档和素材快照；源文件随后变化不能偷换待采用内容，若采用时需要重采且结果变了，刷新候选并重新呈现。操作继续核对当前稿版本，保护尚未落盘的手工编辑；显式采用不自动合并。
- 预览本身不能编辑、自动保存或作为正式 PNG/JPEG 导出对象。正式导出继续读取已保存当前稿。预览旧结果、待处理候选、已提交当前稿的状态不能混用；当前稿读取 hook 只读当前稿，不因界面正在看预览而读错对象。

## 防止同步循环

只订阅 Agent/外部编辑的创作入口及依赖；Bento 当前稿生成的 PPTD 投影、正式存储、预览缓存与渲染输出不进入该创作订阅/产物采集入口。复用已规划的投影与草稿隔离，不依赖临时的 `ignoreNextEvent` 布尔值去猜哪个事件来自应用。Agent 明确将投影用作新的创作草稿后，按新草稿身份观察和校验。

即使误收到应用写入信号，来源分类与无提交副作用仍阻断“反向同步 → 监听转换 → 再提交”。预览不更新读取基线、回合 manifest、当前稿版本或完成状态。回合结束重新采集、校验并提交，不能因已预览而跳过检查；可复用的只是经核对仍相同的计算结果，不是提交授权。

## 阶段与验证

P3.7 实现按需订阅、稳定字节采集、转换调度、只读呈现和外部文件的显式候选入口；P4 完成状态、切换与采用交互，P5 清理时保留仍有消费者的 watcher 基础设施，P6 验证实际安装包。P3.7 可先复用现有正向转换完成切片，不以五种 hook 全部接入或反向转换完成为前置；投影/草稿来源边界须先与 P3.1 对齐。

验收覆盖：分步/同内容写入、素材同路径替换、原子 rename、依赖新增/删除/暂缺、持续写入、监听丢失/失败、多消费者释放、旧转换/旧窗口迟到、有限资源、外部编辑、无消费者后台回合、预览与未保存当前稿并存、源变化后的显式采用，以及同步投影不会产生循环。按既有确定性测试设施规划，用注入通知和可控任务完成顺序，不依赖真实 sleep 或事件时机；平台文件监听实机证据另记。

本轮仅进行源码与方案审查，未运行产品测试、构建、Agent 或实际文件监听。预览载荷、监听基础设施和采集限制为源码证据；持续预览本身尚未实现。三项原待定问题（P2.7 #2b、P2-A3、reference-pack 非 PNG）继续保留，不由本方案顺带裁定。

文档验证：`corepack pnpm run docs status` / `docs check` 无错误，20 条既有大小警告，无注册 SHA topic；`corepack pnpm check:public-boundary` 与 `git diff --check` 通过。Spec 保持 draft，计划与决策保持 proposed，翻译 pending。

提交前验证：`corepack pnpm format`、`corepack pnpm typecheck` 和 `corepack pnpm check:quick` 通过；格式化产生的无关测试文件差异已还原。遵照本轮不运行产品测试的要求，未执行含测试的完整 `pnpm check`，也未进行实际预览/监听验收。
